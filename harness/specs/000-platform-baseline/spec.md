# Propósito

Registrar el sistema que existe al iniciar el proceso SDD. No autoriza cambios de implementación.

# Capacidades conocidas

- Portada pública y blog técnico.
- Registro e inicio local con correo y contraseña.
- Integración opcional con Google OAuth.
- Sesiones persistentes mediante Better Auth.
- Perfiles y niveles de acceso.
- Administración de entradas y usuarios según rol.
- Persistencia D1 mediante Drizzle.

# Restricciones

- La plataforma se ejecuta localmente.
- No existe autorización para publicar o desplegar.
- Los cambios posteriores requieren una especificación numerada nueva.

# Criterios de aceptación de la línea base

- CA-01: El contexto de producto, arquitectura e invariantes está documentado.
- CA-02: Existen plantillas para especificar, planear, dividir y verificar cambios.
- CA-03: El harness puede validarse con un comando local sin dependencias adicionales.
